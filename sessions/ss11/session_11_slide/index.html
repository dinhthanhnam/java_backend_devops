01

Reverse Proxy & Luồng Giao Thức Mạng

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Expose cổng trực tiếp vs Reverse Proxy

Không có Reverse Proxy

  • Mở toang cổng 8080, 8081 ra Internet
  • Hacker dò quét port & tấn công trực diện Spring Boot
  • Phải cấu hình SSL/HTTPS cho từng service riêng lẻ

Có Nginx Reverse Proxy

  • Cô lập toàn bộ cổng backend trong mạng nội bộ
  • Chỉ mở cổng 80/443 ở biên
  • Tập trung giải mã SSL tại Nginx (SSL Termination)

Lưu ý

Expose trực tiếp cổng ứng dụng Spring Boot ra Internet là lỗ hổng bảo mật mức nghiêm trọng.

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Forward Proxy vs Reverse Proxy

Forward Proxy (Proxy Xuôi)

  • Đứng trước Client (Người dùng)
  • Đại diện Client gửi request ra ngoài Internet
  • Mục đích: Vượt tường lửa, ẩn danh IP (VPN, Proxy công ty)

Reverse Proxy (Proxy Ngược)

  • Đứng trước Server (Hệ thống)
  • Đại diện cụm server nhận request đổ vào
  • Mục đích: Định tuyến, bảo mật biên (Nginx)

Cấu trúc Tệp tin Cấu hình Nginx

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Cơ chế nạp cấu hình tự động

Thư mục conf.d/

Nguyên tắc Production

Tuyệt đối không chỉnh sửa tệp tin gốc nginx.conf của hệ điều hành.

  • Trong khối http của tệp gốc có dòng: include /etc/nginx/conf.d/*.conf;
  • Kỹ sư viết tệp cấu hình riêng (ví dụ: quickbite.conf) đặt vào thư mục /etc/nginx/conf.d/
  • Tệp cấu hình con chỉ chứa khối server { ... }, không khai báo lặp http { ... }
© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Khối server và location

listen 80
Lắng nghe cổng HTTP
server_name
Tên miền khớp request (_ = mọi request)
location
Khối xử lý theo đường dẫn URI
quickbite.conf nginx 
server {
    listen 80;
    server_name api.quickbite.com;

    access_log /var/log/nginx/qb.log;
    error_log  /var/log/nginx/qb_err.log;

    location / {
        root /usr/share/nginx/html;
        index index.html;
    }
}

Cấu hình Nginx

Quy tắc ưu tiên so khớp Location

Modifier Loại so khớp Ưu tiên Ví dụ
= Khớp chính xác (Exact) 1 ★ location = /favicon.ico
^~ Tiền tố ưu tiên (không quét Regex) 2 location ^~ /assets/
~ / ~* Regex (có / không phân biệt hoa thường) 3 location ~ \.(jpg|png)$
(không có) Tiền tố mặc định (Prefix) 4 location /api/

03

Thực hành cấu hình Proxy tới API Gateway

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Cấu hình proxy_pass & Headers

  1. 01

    proxy_pass

    Chuyển tiếp tới API Gateway trên localhost

  2. 02

    Host header

    Ghi nhận tên miền gốc của Client

  3. 03

    X-Real-IP

    Truyền IP thật của Client xuống Backend

quickbite.conf nginx 
location /api/ {
    proxy_pass http://127.0.0.1:8080/;

    # Bảo toàn thông tin Client
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For
        $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto
        $scheme;
}

Quy trình DevOps chuẩn khi đổi cấu hình

Zero-Downtime Reload

  • Bước 1

    Lưu file cấu hình tại /etc/nginx/conf.d/quickbite.conf

  • Bước 2

    Kiểm tra cú pháp: sudo nginx -t → syntax is ok

  • Bước 3

    Nạp nóng: sudo systemctl reload nginx

Cảnh báo

Tuyệt đối không dùng restart trên Production — sẽ ngắt quãng kết nối hiện tại của khách hàng.

HTTPS & Chứng chỉ SSL

🔒

Tại sao cần HTTPS?

HTTP truyền tin dạng Plaintext — dễ bị nghe lén (Man-in-the-middle). HTTPS mã hóa toàn bộ dữ liệu: JWT Token, Password, thông tin thẻ ngân hàng.
🤖

Certbot & Let's Encrypt

Cung cấp chứng chỉ SSL miễn phí. Certbot tự xác thực tên miền và ghi đè cấu hình SSL an toàn vào file Nginx.

SSL Termination & Redirect 301

SSL Termination

  • Client gửi HTTPS (cổng 443) tới Nginx
  • Nginx giải mã SSL → HTTP thường
  • Chuyển tiếp HTTP tới API Gateway (localhost:8080)
  • Giải phóng CPU cho container Java

Redirect 301

  • User gõ http://api.quickbite.com
  • Nginx trả 301 Moved Permanently
  • Trình duyệt tự chuyển lên https://

Mẹo

Certbot tự cấu hình cron job gia hạn chứng chỉ trước khi hết hạn 90 ngày.

Những lưu ý quan trọng khi triển khai Nginx

  • Luôn cô lập cổng Microservices — chỉ mở 80/443 qua Nginx
  • Tận dụng thư mục conf.d/ để nạp cấu hình tự động, không sửa nginx.conf
  • Kiểm tra cú pháp bằng nginx -t trước khi systemctl reload nginx
  • Cấu hình X-Real-IP để backend nhận biết IP thật của Client
