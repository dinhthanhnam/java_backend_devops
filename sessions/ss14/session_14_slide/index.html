Grafana và Vai trò Trực quan hóa Hệ thống

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Hạn chế của Prometheus UI

Tại sao cần thêm một tầng trực quan hóa?

Prometheus UI thô sơ

  • Chỉ hiển thị biểu đồ đơn lẻ cho từng truy vấn PromQL
  • Không thể gộp nhóm đồ thị thành một bảng điều khiển (Dashboard)
  • Không hỗ trợ phân quyền người dùng (RBAC), không màn hình login

Grafana chuyên nghiệp

  • Tổng hợp hàng chục biểu đồ trên một màn hình duy nhất
  • Dashboard lưu trữ động, xem real-time tiện lợi
  • Hệ thống bảo mật và phân quyền tài khoản chặt chẽ

Lưu ý

Để lộ giao diện thô Prometheus ra ngoài là lỗ hổng bảo mật. Grafana cung cấp cổng bảo mật đăng nhập.

Luồng Dữ liệu Giám sát

Kiến trúc 3 tầng tiêu chuẩn

Targets (JVM / VPS)
Expose cổng metrics dạng text
Prometheus Server
Pull metrics & lưu chuỗi thời gian
Grafana
Gửi PromQL truy vấn hiển thị

Mô tả kiến trúc

Giải thích 3 phân lớp chính

  • Lớp Thu thập: Spring Boot Actuator và Node Exporter định kỳ mở metrics.
  • Lớp Lưu trữ: Prometheus kéo dữ liệu (Pull) lưu vào ổ TSDB.
  • Lớp Hiển thị: Grafana kéo dữ liệu từ Prometheus API để xuất đồ thị lên Dashboard.

Cấu hình Docker Compose cho Grafana

Thêm dịch vụ vào file docker-compose.yml hạ tầng

docker-compose.yml yaml 
grafana:
  image: grafana/grafana:10.0.3
  container_name: quickbite-grafana
  ports:
    - "3000:3000"
  volumes:
    - grafana-data:/var/lib/grafana
  networks:
    - quickbite-net
  environment:
    - GF_SECURITY_ADMIN_PASSWORD=admin_secure_pass
  restart: unless-stopped

Cảnh báo

Mount volume grafana-data là bắt buộc để lưu trữ tài khoản và thiết kế các Dashboard khi container restart.

02

Kết nối Grafana với Nguồn dữ liệu Prometheus

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Liên kết nguồn dữ liệu

Thiết lập Prometheus Data Source

  1. 01

    Data Sources

    Vào Connections → Chọn Data sources

  2. 02

    Chọn Prometheus

    Bấm Add data source → Chọn Prometheus

  3. 03

    Nhập URL

    Điền URL nội bộ mạng Docker

Cấu hình URL kết nối

Sử dụng tên DNS nội bộ

Prometheus URL
http://quickbite-prometheus:9090

Mẹo

Không cần mở cổng 9090 ra Internet. Grafana và Prometheus kết nối hoàn toàn trong mạng nội bộ Docker.

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Tại sao không dùng localhost?

Nguyên lý định tuyến mạng nội bộ Docker

SAI — Dùng localhost / 127.0.0.1

  • URL cấu hình: http://127.0.0.1:9090
  • Lỗi: Thất bại (Connection Refused)
  • Nguyên nhân: Trỏ về chính container Grafana, không có Prometheus chạy trong đó

ĐÚNG — Dùng Docker DNS

  • URL cấu hình: http://quickbite-prometheus:9090
  • Kết quả: Thành công (Successfully queried)
  • Nguyên nhân: Docker Network tự động phân giải tên container thành IP nội bộ chính xác

Mẹo

Hãy luôn dùng tên container (service name) để thiết lập kết nối giữa các dịch vụ chạy chung docker-compose.

Tận dụng Dashboard cộng đồng

Tiết kiệm thời gian thiết kế biểu đồ

  1. 01

    Copy ID

    Tìm kiếm Dashboard trên grafana.com/dashboards và copy ID mẫu

  2. 02

    Dán ID

    Trong Grafana, vào Dashboards → New → Import và dán ID mẫu

    Liên kết

    Chọn Data source là Prometheus và bấm Import để nạp giao diện

Truy vấn PromQL thực tế

Cách đo lường CPU của VPS

PromQL
# Tính % CPU đang sử dụng (Rate)
100 - (avg by (instance) (
  rate(node_cpu_seconds_total{
    mode="idle"
  }[5m])
) * 100)

Cấu hình Cảnh báo Tự động (Alerting)

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Luồng hoạt động của Alerting

Từ lúc xảy ra sự cố đến khi thông báo tới DevOps

1. Quét chỉ số CPU VPS vượt quá 90%
Kích hoạt
2. Đánh giá Rule Duy trì quá 5 phút
Firing
3. Phát cảnh báo Gửi webhook tin nhắn
Nhận
4. Telegram / Slack Kênh liên lạc DevOps

Ghi nhớ

Alerting giúp DevOps giải phóng sức lao động, không cần túc trực 24/7. Hệ thống tự động báo động khi xảy ra lỗi.

© 2026 By Rikkei Academy - Rikkei Education - All rights reserved.

Thiết lập cảnh báo

Từng bước cài đặt Alerting

  1. 01

    Contact Point

    Khai báo kênh nhận tin (Telegram Webhook)

  2. 02

    Alert Rule

    Viết PromQL để theo dõi ngưỡng vi phạm

  3. 03

    Pending duration

    Đặt thời gian trễ (ví dụ: vi phạm liên tục 2 phút)

Ví dụ thực tế

Theo dõi sập Microservice

PromQL Alert Rule
# Trả về 0 khi service không phản hồi
up{application="order-service"} == 0

Lưu ý

Tránh đặt thời gian trễ (Pending duration) quá ngắn nhằm hạn chế cảnh báo ảo (Flapping Alerts) khi CPU chỉ bị nhói tức thời.
